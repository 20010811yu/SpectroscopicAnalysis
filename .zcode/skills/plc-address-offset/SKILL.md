# PLC 地址偏移排查（Modbus TCP）

## 已知结论（本项目现场实测）

- 本现场 PLC 的 Modbus 地址存在**固定偏移量 2**：按配置的寄存器地址直读读不到正确数据，需在地址上补偿偏移才能命中真实寄存器。
- 换算方向（`协议地址 = 配置地址 + 2` 还是 `- 2`）以探针工具实测为准，定位后必须回写本节与统一配置，后来者不得再自行猜测。
- **偏移由通信层统一应用**：定位后写入统一设备配置（如 `Devices:Plc:Registers` 或新增 `AddressOffset` 字段），在读地址处统一换算。**禁止**在各调用点手工加减偏移（避免多处不一致）。

## 排查清单（按命中概率排序）

1. **0 基 / 1 基差 1**：Modbus 协议 PDU 地址从 0 开始，文档/组态常写 1 基（如 40001 表示协议地址 0）。差 1 先试。
2. **本项目实测偏移 ±2**：存在固定偏移 2，用探针工具在候选偏移 `-4,-2,-1,0,1,2,4` 中扫描比对确认。
3. **功能区混淆**：保持寄存器用功能码 0x03/0x06/0x10，输入寄存器用 0x04，线圈用 0x01/0x05。写的是保持寄存器地址却用 0x04 读，自然读不到。
4. **字节序/字交换**：若"地址能读到数据但数值不对"，多为大小端或字交换（ABCD/CDAB）问题，不是地址偏移；先看 hex 原始值再下结论。
5. **Unit ID / 槽位**：多从站或多 CPU 网关时 Unit ID 不对会返回异常码或读到别的从站数据。

## 验证方法（探针工具）

用 `scripts/offset-probe.cs`（纯标准库单文件 C#，`dotnet run scripts/offset-probe.cs` 运行，无第三方依赖）：

```bash
dotnet run --file .zcode/skills/plc-address-offset/scripts/offset-probe.cs -- \
  --host 192.168.0.1 --port 502 --unit 1 \
  --start 4000 --count 4 --sweep 2 --offsets "-4,-2,-1,0,1,2,4"
```

- 对配置基准地址及各候选偏移各读一次保持寄存器（0x03），输出「偏移 → 寄存器原始值（十进制 + hex）」对照表。
- 与 PLC 侧已知期望值（如心跳递增计数、固定状态字）比对，命中行即真实偏移。
- 建议先用**变化可知的寄存器**（心跳计数）验证：哪个偏移下数值在按节拍递增，哪个就是对的。

## 定位后的落地步骤

1. 把偏移写入统一设备配置（`appsettings.json` 的 `Devices` 节），禁止代码内写死数字。
2. 通信实现层在读/写前统一应用偏移，并在 PLC 通讯日志中记录"配置地址 → 实际协议地址"换算，便于追溯。
3. 回写本 SKILL.md「已知结论」节：偏移方向、验证日期、涉及寄存器区，保持知识库与现场一致。
4. 按 AGENTS.md 错误库要求，若属新踩坑，追加到 `docs/错误收集与避免.md`。
