# 错误收集与避免

> 目的：沉淀本项目开发中实际踩过的编程错误与修复方法，AI 编码助手执行任务前先通读本文，**同类错误不得再犯**。
> 维护规则：每次修复一个新错误，按分类追加条目（现象 / 原因 / 正确做法 / 案例）；条目要写"怎么改对"，不写流水账。

---

## 1. WPF 模板与 XAML 类错误

### 1.1 DataGrid 行模板：裸 `DataGridCellsPanel` 无数据源（已实际踩坑 2 次）

- **现象**：自定义 `DataGridRow` ControlTemplate 后，整行不按列渲染，只显示行对象的 `ToString()`（如 `SpectroscopicAnalysis.Host.ViewModels.SampleRowItem`）。
- **原因**：`DataGridCellsPanel` 只是排列面板，不是 ItemsControl，直接放进模板没有单元格数据源。单元格必须由 **`DataGridCellsPresenter`**（ItemsControl）承载，`DataGridCellsPanel` 是它经 `ItemsPanel="{TemplateBinding ItemsPanel}"` 自动生成的 ItemsPanel。
- **正确做法**：行模板内使用
  ```xml
  <DataGridCellsPresenter Grid.Column="1" Grid.Row="0"
                          ItemsPanel="{TemplateBinding ItemsPanel}"
                          SnapsToDevicePixels="{TemplateBinding SnapsToDevicePixels}" />
  ```
- **验证方法**：写最小 WPF 复现程序（`RenderTargetBitmap` 渲染成 PNG 自查），不要只靠 build 通过就提交。
- **案例**：`Themes/Styles.xaml` 的 `GridRow` 样式（commit `4c9766c`）。

### 1.2 DataGrid 行模板：保留 `DataGridDetailsPresenter` 会渲染多余杂行（已实际踩坑）

- **现象**：单元格已正常，但每行上/下多出一行行对象 `ToString()` 文本。
- **原因**：项目从不使用行详情（RowDetailsTemplate 为 null），但模板里放了 `DataGridDetailsPresenter`，它仍会以行对象为内容渲染。
- **正确做法**：不用行详情就把 `DataGridDetailsPresenter` 从模板中移除；只有确实施加行详情时才保留并配好 `RowDetailsVisibilityMode`。同理，`HeadersVisibility="Column"`（行头未使用）时 `DataGridRowHeader` 也不要放进模板——其默认模板带边框，会在第一列左侧残留竖向分割线（commit `eb9d0e1`）。
- **案例**：同上（commit `4c9766c`）。

### 1.3 XAML 属性重复设置（已实际踩坑）

- **现象**：编译错误 `MC3024：已设置"X.Style"属性，并且只能设置一次`。
- **原因**：同一元素上既写了 `Style="{StaticResource Xxx}"` 特性，又写了 `<X.Style>` 内联样式元素；或想基于某个样式扩展触发器时忘了删掉特性。
- **正确做法**：需要基于现有样式扩展触发器时，**只保留** `<X.Style><Style BasedOn="{StaticResource Xxx}" TargetType="X">…` 内联写法，删除 Style 特性。
- **案例**：`Views/SamplesPage.xaml` 详情面板 Border 与占位 TextBlock（commit `8713829`）。

### 1.4 XAML 中不存在的属性/元素（已实际踩坑）

- **现象**：写了 `<RowDefinition.Resources />` 之类不存在的成员，编译报错或行为异常。
- **原因**：凭记忆拼 XAML 结构，未确认该元素/属性真实存在。
- **正确做法**：不确定的资源作用域、附加属性、模板部件名，先查证（官方文档或参考源码），再写；不要用"看起来合理"的结构。

### 1.5 布局元素跨行/跨列遮挡相邻区域（已实际踩坑）

- **现象**：分页脚消失。
- **原因**：右侧详情面板 `Grid.RowSpan="3"` 横跨到分页栏所在行，卡片背景绘制在其上层（文档序靠后 Z 序更高）盖住分页脚。
- **正确做法**：同格叠放布局中，侧栏/浮层元素只占自己的目标行；跨 `RowSpan` 前先检查覆盖到的行里是否有需要交互/可见的控件。
- **案例**：`Views/SamplesPage.xaml` 详情面板（commit `fb345a0`）。

### 1.6.1 HandyControl 隐式样式在选中时改 Background/BorderBrush（已实际踩坑 3 次）

- **现象**：DataGrid 首行（默认选中行）反复出现边框/阴影，去掉行模板描边后仍有，再去掉单元格模板边框后仍残留。
- **原因**：App.xaml 合并了 HandyControl 主题，其针对 `DataGridRow`/`DataGridCell` 的隐式样式触发器在 `IsSelected/IsFocused/IsMouseOver` 时会设置 `Background` 与 `BorderBrush`。自定义样式若只重置 `Background` 不重置 `BorderBrush`，选中行仍残留边框。
- **正确做法**：行/单元格样式的选中触发器必须**成组重置** Background + BorderBrush（+Foreground）；单元格模板用 `BorderThickness/BorderBrush` 的 TemplateBinding，边框属性整体透明。
- **验证方法**：最小复现程序可离线引用 HandyControl 包（同版本 NuGet 缓存），用 `pack://application` 前需先 `new Application()` 注册 pack URI；`RenderTargetBitmap` 渲染 PNG 自查。
- **案例**：`Themes/Styles.xaml` 的 `GridRow`/`GridCell`（commits `6f8fa70`、`654f03c`、`4618258`）。

### 1.7 构建报 exe 被锁定（MSB3027/3021）≠ 代码错误（已实际踩坑）

- **现象**：`dotnet build` 报"无法复制 apphost.exe 到 Host.exe，文件被另一进程锁定"，重试 10 次失败。
- **原因**：用户正在运行 `SpectroscopicAnalysis.Host.exe`，复制产物被锁；XAML/代码编译实际已通过。
- **正确做法**：先区分错误类型——只有 MSB3027/3021 且指向 Host.exe 时，说明是应用在运行，请用户关闭应用后重建即可；不要误判为代码错误去"修代码"。

### 1.8 DataTrigger 绑定了行模型上不存在的属性：静默失效不报错（已实际踩坑）

- **现象**：状态徽章的失败色触发器 `<DataTrigger Binding="{Binding HasFailure}" Value="True">` 永远不生效，行一直显示默认色；构建通过、无任何绑定报错。
- **原因**：XAML 里先写了触发器，行模型（`ProductionRowItem`）却没定义 `HasFailure` 属性——WPF 绑定失败走静默降级（输出窗口才有提示），触发器按"不匹配"处理。
- **正确做法**：在 XAML 中引用行属性前先确认模型已定义（新增视图触发器时同步加行属性并重新构建）；排查时优先用 `grep 属性名 模型文件` 核对，而不是反复调样式。
- **案例**：`ProductionRowItem.HasFailure`（commit `57f08e3`）。

### 1.5 元素提取/重构时破坏大括号结构（已实际踩坑 2 次）

- **现象**：C# 表达式体方法（`=> new() { … }`）把初始化器缩进改乱后留下孤立大括号，报 `CS8803 / CS0106 / CS1022`（顶级语句/修饰符无效）连锁错误，一次 46~186 个错误。
- **原因**：用编辑替换抽取私有 `Map(reader)` 方法时，只替换了方法头，方法体的大括号层级没有同步收敛。
- **正确做法**：重构"对象初始化器 → 表达式体返回"时，**方法头和方法体一次性替换完整**，替换后立即 `dotnet build` 验证；连锁报错时先看第一个错误行，通常是结构问题而非逐个修。
- **案例**：`SctCertifiedValueRepository.cs` / `SctOperationLogRepository.cs` 抽取 `Map` 方法（commit `8713829`）。

### 1.x 元素特性上的本地值优先级高于样式触发器 Setter，触发改不动文案（已实际踩坑）

- **现象**：主控台激光打标在线徽章，`<TextBlock Text="● 离线">` 特性上写了默认文案、样式 DataTrigger 里 Setter 切 `Text="● 在线"`——运行时徽章底色随 IsOnline 变绿（Border 无本地值，触发生效），但文字始终显示"离线"。
- **原因**：WPF 依赖属性优先级中**本地值（元素特性直接赋值）高于样式触发器 Setter**；`Text` 被本地值钉死，触发器的 Text Setter 永远不生效。Foreground 无本地值所以切换正常，形成"底色变了文字不变"的迷惑现象。
- **正确做法**：需要被触发器切换的属性**一律由样式 Setter 提供默认值**（写在 `<Style>` 的 `<Setter Property="Text" Value="默认"/>`），元素特性上不得再写该属性；同一元素的同一属性不能既挂 Style 特性又写 `<元素.Style>`（MC3024 重复设置，同样踩过）。
- **案例**：ConsolePage 激光打标在线徽章文案（commit `1eabb40`）。

## 2. 状态与选中联动类错误

### 2.1 行集合整体替换后选中/详情失效

- **现象**：分页、筛选、删除后，右侧详情面板内容与表格选中行脱节或残留旧数据。
- **原因**：本项目 VM 的行集合每次分页都整体 `new ObservableCollection` 替换，旧行对象引用不再在表格中。
- **正确做法**：集合替换后按业务键（SampleID）重选；重选失败回退到第一行（详情面板默认有内容）；后台异步填充详情时用引用比对（`ReferenceEquals(SelectedRow, row)`）丢弃过期查询结果，防止旧查询覆盖新详情。
- **案例**：`SamplesViewModel.RestoreSelection()` / `RefreshDetailAsync()`（commit `8713829`、`67322ad`）。

### 2.2 接口新增方法后 Fake/Stub 未同步实现

- **现象**：主工程编译通过，测试工程报 `CS0535: "FakeXxx" 不实现接口成员`。
- **原因**：给仓储接口加方法时只改了实现类，漏了测试工程里的 Fake 类。
- **正确做法**：改接口后用全局搜索接口名，把所有实现（含 tests 下的 Fake/Stub）一并补齐；或加完接口立即 build 整个解决方案（含测试工程）而不是单项目。
- **案例**：`ISctCertifiedValueRepository.GetBySampleId` / `ISctOperationLogRepository.GetRecentBySampleId`（commit `8713829`）。

### 2.3 共享 SelectedRow + 强类型 RelayCommand&lt;T&gt;：类型不符的 CanExecute 直接抛异常崩进程（已实际踩坑）

- **现象**：生产样档案页一切到该表或点"下一页"，界面随即卡死/进程消失（用户感知为"点击下一页界面卡死"）。事件日志：`System.ArgumentException: Parameter "parameter" cannot be of type ProductionRowItem, as the command type requires SampleRowItem`。
- **原因**：样品台账与生产样档案两张 DataGrid 共用 VM 的 `SelectedRow`（object），详情面板"删除样品"按钮 `CommandParameter="{Binding SelectedRow}"` 绑到强类型 `[RelayCommand] DeleteAsync(SampleRowItem?)`。切到生产样表后 `SelectedRow` 变为 `ProductionRowItem`，按钮虽 `Visibility=Collapsed`，WPF 在 `CommandParameter` 变化时仍会求值 `CanExecute`——CommunityToolkit.Mvvm 的 `RelayCommand<T>` 对类型不符参数**抛 ArgumentException 而非返回 false**（CanExecute/Execute 均如此），未捕获异常直接终止进程。按钮隐藏挡不住这条路径，与用户是否点击无关（启动时恢复上次的表选中行即可复现）。
- **正确做法**：绑定共享 `SelectedRow` 的命令参数一律用 `[RelayCommand] private ... Xxx(object? parameter)`，方法内 `is not T` 宽容纳型后 return；不要对来自共享选中行的参数使用强类型 `RelayCommand<T>`。
- **案例**：`SamplesViewModel.DeleteAsync`（commit `9ade165`）。
- **附带教训（环境）**：Write 工具输出的 .ps1 为无 BOM UTF-8，Windows PowerShell 5.1 按 ANSI 解析，中文字符串可能吞掉闭合引号导致整脚本解析失败（报错行还指向别处）；脚本里的中文一律用 `[char]0x4E0B` 码位拼接，或落盘为带 BOM 的文件。

### 2.4 DataGrid 行选中高亮写在 Style.Triggers 不生效：RowBackground 本地值压制样式触发器（已实际踩坑）

- **现象**：给 `GridRow` 样式的 `IsSelected` 触发器设置 `Background` 选中高亮后，构建通过但点行仍无任何高亮。
- **原因**：页面 XAML 给 `DataGrid` 设了 `RowBackground="Transparent"`（AlternatingRowBackground 同理），DataGrid 生成行容器时会把 RowBackground 以**本地值**（Local Value）写进行元素；WPF 依赖属性优先级中本地值高于样式触发器，`Style.Triggers` 里的 `Background` Setter 永远被压掉，XAML 不报错、构建不失败，纯静默失效。
- **正确做法**：行选中高亮写进 `ControlTemplate.Triggers`，用 `Setter TargetName="行内Border" Property="Background"` 直接作用于模板内元素（模板触发器 > 模板绑定/本地值链路），不受本地值压制；`Style.Triggers` 里的同义触发器不要保留双份。
- **案例**：`Themes/Styles.xaml` GridRow 模板触发器（commit `5f056f1`）。

### 2.6 命令参数类型必须与绑定源一致：string 命令 + long 绑定 = UI 线程崩溃（已实际踩坑）

- **现象**：`AckAlarmCommand`（`RelayCommand<string>`，`AckAlarm(string alarmId)`）绑定 `CommandParameter="{Binding AlarmId}"`（long）。程序运行多日不崩，一旦报警行首次出现，切到含报警面板的页面即 `[FTL] UI 线程未处理异常`：`Parameter cannot be of type System.Int64, as the command type requires System.String`，进程直接崩溃。
- **原因**：`RelayCommand<T>.CanExecute/Execute` 对参数类型强校验，类型不符抛 `ArgumentException`；该异常发生在 WPF 数据绑定激活（ButtonBase.UpdateCanExecute → DataBindEngine）内，属 UI 线程未处理异常。**隐蔽性**：面板为空时按钮根本不实例化，绑定不激活——错误潜伏到"第一条数据出现"才爆，构建期完全无感。
- **正确做法**：命令参数类型与绑定源属性类型严格一致（本例改为 `AckAlarm(long alarmId)`）；新增带参命令时核对 CommandParameter 绑定的源属性类型，string 化转换不要放在命令签名上（要转在 XAML 转换器或模型属性里）。同类坑见 2.3（共享 SelectedRow 强类型命令）。
- **案例**：`ConsoleViewModel.AckAlarm` + `ConsolePage.xaml` 报警确认按钮（commit `4814d02`）。

### 2.5 表单行改 StackPanel 后外层仍留 Grid：所有行叠在同一单元格（已实际踩坑）

- **现象**：把表单各行从 Grid.Row 布局改为横向 StackPanel 后，界面所有行标题/输入框全部重叠在第 0 行位置。
- **原因**：外层容器仍是 Grid 但未定义 RowDefinition，Grid 所有子元素默认布局在 (0,0) 单元格，纵向堆叠必须由外层容器自己提供——Grid 不会自动竖排。
- **正确做法**：行式布局的外层容器用纵向 `StackPanel`（或补齐 Grid.RowDefinitions）；改动布局容器类型时必须连同开闭标签一起替换，不要只换内层。
- **案例**：`SamplesPage.xaml` 样品注册表单（commit `3026c56` → `03c02b7`）。

## 3. 数据层错误

### 3.1 外键删除行为按语义选择，不默认 CASCADE

- **规则回顾**：系数表来源样品 `ON DELETE SET NULL`（版本保留、来源置空）；分析结果 `ON DELETE CASCADE`（从属数据随主删）；操作日志**故意无外键**（审计不可随样品删除丢失）。新表设计时先判断"数据是否必须比主表活得久"，审计类一律软关联。

### 3.2 SQLite UPDATE 关联子查询：目标表不能起别名，须用表全名引用（已实际踩坑）

- **现象**：`UPDATE CorrectionCoefficient SET IsCurrent = CASE WHEN CoeffID = (SELECT c2.CoeffID FROM CorrectionCoefficient c2 WHERE c2.MethodID = c.MethodID AND c2.Element = c.Element ...)` 执行报 `Parse error: no such column: c.MethodID`——解析器不认识 UPDATE 目标表的别名 `c`。
- **原因**：SQLite 的 UPDATE 语句不像 SELECT 那样给目标表起别名（`UPDATE 表 别名` 语法不存在）；关联子查询里引用目标表行只能写全名。PostgreSQL/SQL Server 里 `UPDATE 表 AS c` 的习惯写法照搬过来必踩。
- **正确做法**：子查询中用表全名引用外层行：`WHERE c2.MethodID = CorrectionCoefficient.MethodID AND c2.Element = CorrectionCoefficient.Element`。
- **附带教训（同一问题）**：版本化表若建表时缺 `UNIQUE(分组键, 版本)` 唯一索引，`INSERT OR IGNORE` 退化为普通 INSERT，重复播种（或重复导入）会叠加出成倍冗余行、且每轮各自的"当前有效"标记同时存在（同组多条 IsCurrent=1）。修复模式：先按（分组键, 版本）去重保留最小主键 → 按"生效时间最新"归一化有效性标志 → 再建唯一索引（顺序不能颠倒，存量有重复时唯一索引建不起来）；全部幂等放建表初始化中。
- **案例**：`DbInitializer.DedupeAndNormalizeCoefficients`（commit `4c8debb`）。

### 3.3 写库前必须核对外键指向：跨表写入会每次失败并连锁触发 UI 崩溃（已实际踩坑）

- **现象**：把 SCT 样的激发结果写进 `Analysis_Result`，每次执行报 `SQLite Error 19: FOREIGN KEY constraint failed`（被错误链捕获成报警），且连续报警最终引爆 2.6 的命令参数崩溃。
- **原因**：`Analysis_Result.SampleID REFERENCES Production_Sample`（该表按任务清单定位为生产样归档表），SCT 样 ID 不在主表，插入必违外键；仓储方法能编译、测试用 Fake 仓储（无外键约束）全绿，只有连真库才炸。
- **正确做法**：新增写库调用前核对目标表的建表外键定义（`REFERENCES` 指向哪张主表），**先按主表身份过滤再插入**（本例：`ArchiveSparkResult` 先确认 sampleId 存在于 Production_Sample，SCT 样审计走 `SCT_OperationLog`）；外键冲突不要只当孤立数据问题——它产生报警会沿错误链传导到 UI 层。
- **案例**：`WorkflowOrchestrator.ArchiveSparkResult`（commit `4814d02`）。

### 3.4 同一任务的审计日志禁止多点写库：一任务一行（已实际踩坑）

- **现象**：一次控制检查在生产日志中出现两行记录（编排器 `WriteTrace` 写"人工触发"行带起止时间，引擎 `NotifyControlResult` 写"检查样检查"行带 IsPass），测高任务同样双写（"测高回填"行与轨迹行重复）。两条记录信息互补却重复展示，用户误以为执行了两次。
- **原因**：引擎与编排器各自为审计写同一张 `SCT_OperationLog`，缺少"唯一写点"约定；引擎侧虽已注释"入队不再单独写日志、一行一任务"，但只消掉了入队行，结果回喂点的写库遗留。
- **正确做法**：**同一任务在 `SCT_OperationLog` 只允许编排器完成行一个写点**，任务执行期产生的结果数据（合格判定 IsPass、测高前后厚度）由编排层经方法返回值带回并入完成行（`WriteTrace` 扩展可选参数）；引擎回喂方法（`NotifyControlResult`/`NotifyHeightMeasured`）只做状态流转不写日志。新增回喂点时先确认写库归属，勿再各写一条。
- **案例**：`WorkflowOrchestrator.WriteTrace` 合并引擎双写（本次修改）；测试同步改为断言引擎不写日志。

## 4. 环境与工具链注意事项

### 4.1 本机工具可用性（每次会话先探明）

- `dotnet` 报 "It was not possible to find any installed .NET Core SDKs"：机器 PATH 中曾有 `C:\Program Files (x86)\dotnet\`（3.1 时代无 SDK 的 x86 残留）排在 `C:\Program Files\dotnet\`（SDK 10.0.404）之前。注意 Windows 有效 PATH = 机器级在前 + 用户级在后，**前置用户级 PATH 无法覆盖机器级条目**；DOTNET_ROOT 对旧 x86 host 也无效。最终修复：管理员提权从机器级 PATH 删除 x86 条目（2026-11-13，脚本 D:\tmp\fixpath.ps1 模式：写 ps1 → `Start-Process -Verb RunAs -Wait` → 完成标记文件确认）。

- `git` 不在 PATH，实际位置 `D:\Git\Git\bin\git.exe`；提交统一用全路径调用。
- `findstr/grep/tail/head` 等在部分调用环境不可用，优先用 PowerShell（`Select-String`、`Select-Object -Last`）。
- `dotnet` 不在 PATH，实际位置 `C:\Program Files\dotnet\dotnet.exe`；SDK 为 **10.0.404**（无 SDK 8），目标框架 `net10.0-windows`。
- PowerShell 输出中文为 GBK 乱码：判断构建结果看错误码/数字（`0 警告 0 错误`、`已通过: 130`），不要依赖中文文本匹配。

## 5. 编码规范类易错点（复述防忘）

1. ViewModel 禁止引用 WPF 类型（Brush/Color/Window 等），颜色一律由 XAML 的 Style/DataTrigger 按 Status 枚举映射 `Brush.*` 资源。
2. 颜色/字号不得硬编码 Hex 或数值，一律 `Brush.*` / `Typography` 资源；灰体字（次要/禁用灰）仅限描述性说明文字，功能性节点文字用主文字色（见界面设计规范 3.2）。
3. 内容容器禁止固定宽高（图标白名单除外），用 Grid+Star 比例 + MinWidth。
4. `async` I/O 禁止 `.Result/.Wait()`；I/O 放 `Task.Run`，结果经 `IUiDispatcher` 回 UI 线程。
5. 错误必须走统一错误链（`IErrorCollector` + `ErrorCodes` 常量），禁止空 catch、禁止错误码 magic number。
6. 异常 `catch` 必须有语义注释说明预期路径（如 `OperationCanceledException` 的优雅停止）。
